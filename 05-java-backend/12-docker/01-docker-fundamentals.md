# Docker and Backend Deployment

## 1. What Is It?
Docker is a platform that uses OS-level virtualization to deliver software in packages called **containers**. A container includes everything needed to run an application: the code, runtime (JRE), system tools, libraries, and settings. 

## 2. The Problem It Solves
"It works on my machine!" 
Before Docker, deploying a Java application meant configuring a specific OS version, installing the exact JDK, setting environment variables, and configuring Tomcat manually. Docker guarantees that the environment the application runs in locally is identical to the environment in production.

## 3. Core Concepts
- **Image:** A read-only, static template containing instructions for creating a container (like a Class in Java).
- **Container:** A running instance of an image (like an Object in Java).
- **Dockerfile:** A text document containing all the commands to assemble an image.
- **Volume:** A mechanism to persist data generated by a container. If you run a PostgreSQL container without a volume, deleting the container deletes the database.
- **Network:** Allows containers to talk to each other securely without exposing ports to the host machine.

## 4. JVM Inside Containers (Important Production Concept)
Older versions of Java (Java 8 before update 191) were not "container-aware." The JVM would look at the host machine's total RAM (e.g., 32GB) and set its Max Heap Size to 1/4 of that (8GB), ignoring the fact that Docker restricted the container to 1GB of RAM. The JVM would request memory beyond the container limit, causing Linux to instantly kill the container with an **OOMKilled** error.
Modern Java (11, 17+) correctly reads cgroup limits. However, you should still explicitly set memory limits in your `Dockerfile` (e.g., `ENTRYPOINT ["java", "-Xmx512m", "-jar", "app.jar"]`).

## 5. Multi-Stage Builds
A technique to keep production images tiny. 
- Stage 1 uses a heavy JDK image (with Maven/Gradle) to compile the code and build the `.jar`.
- Stage 2 uses a tiny JRE image (like Alpine or distroless), copies ONLY the final `.jar` from Stage 1, and discards all the heavy build tools.

## 6. Docker Compose
A tool for defining and running multi-container Docker applications using a `docker-compose.yml` file.
*Backend Use Case:* A single command (`docker-compose up`) spins up your Spring Boot app, a PostgreSQL database, a Redis cache, and a Kafka broker simultaneously for local development.

## 7. Interview Questions
### Q. What is the difference between an Image and a Container?
**Short Answer:** An image is an immutable, static snapshot of an application and its environment. A container is a running instance of an image. You can run hundreds of containers from a single image.

### Q. How do you handle secrets (like database passwords) in Docker?
**Short Answer:** Passwords should never be hardcoded in the `Dockerfile` or committed to source control. They should be passed into the container at runtime using Environment Variables (`ENV`) or mounted using Docker Secrets / Kubernetes Secrets, and consumed by Spring Boot via `${DB_PASSWORD}` in the `application.yml`.
